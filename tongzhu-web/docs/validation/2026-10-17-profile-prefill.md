# 个人资料预填发布表单（2026-10-17）

基线v29 / 057ae64。用户要求：先填好的个人信息，在发布时自动带到相应字段。本轮无数据库迁移，不新增第三方服务或付费功能。

## 行为

- 快速发布读取当前登录用户资料，带入昵称（不带系统默认“新用户”）、职业、性别、预算、入住时间、同城区域、室友期待和微信/电话；求租才带住房偏好及已完成资料中的预计租住月数。房源描述和最低起租月数不从个人住房偏好/租住时长推断。
- 新完整发布补齐求租描述和已保存租住时长，保留原有预算、日期、区域、习惯和室友期待默认值；原帖字段优先，不把新的资料覆盖到编辑中的内容。
- 新表单可预览并使用本人资料中已上传的头像，也可上传新头像或选择系统默认。服务端只从当前认证账号读取资料头像，忽略客户端指定的头像URL；新上传优先，编辑保留原头像，修改个人头像不会重写旧帖头像。
- 登录后只补空白字段；已手填内容、主动清空的字段及当前草稿有优先权，联系方式类型切换时可带入对应的已保存号码。草稿按账号和有房/求租分开保存，避免把自动填入的联系方式带到其他账号或不同类型的描述里。
- 联系公开范围、成年/公开声明、房源发布权限确认不从个人资料自动勾选，仍由本次发布单独确认。个人介绍继续在“我的”统一维护并同步显示，不复制成房子描述。
- 旧版全局草稿没有账号归属，不自动导入已登录账号；匿名同类型旧草稿仍可恢复，登录前正在填写的内容仍保留。新逻辑不会在已登录账号打开表单时删除这份不明归属旧草稿。不得把按账号分键的本机存储称为加密隔离。

## 验证

先用实际React服务端渲染在旧表单复现昵称未带入，再修改代码使其通过。当前20组本地检查通过：17组API/业务（既有15组、landlord-agent、profile-avatar），2组React服务端渲染（business-render、profile-prefill-render），1组字段映射/合并单元测试（profile-prefill）。构建及TypeScript通过。

新增检查覆盖资料字段映射、保留草稿/手填与主动清空、微信/电话选择、同城区域、房源/求租描述区分、默认名/时长不乱填、账号草稿键、头像所有权；真实接口验证本人头像复用、忽略客户端URL、拒绝跨账号/匿名复用、默认头像退出、编辑保留与新上传覆盖。渲染检查核对新表单实际值、原帖字段不被覆盖和未自动勾选公开授权。

测试仅写独立本地D1/R2，未提交生产测试账号/帖子。服务端渲染与单元测试不等于完整浏览器的登录后表单交互；本轮没有可用Browser js/CUA工具，微信/抖音实体手机及完整浏览器交互仍待验证。发信配置及真实运营资料缺口不由本轮解决。

Sites发布结果、源提交和GitHub待批次同步状态见根HANDOFF；按用户最新规则先本地commit，不逐次push GitHub。

## 首先只读确认

1. 核对实际环境 ID、数据库是 PostgreSQL、套餐仍为免费体验，没有启用付费/到期自动转付费。
2. 返回可部署的普通云函数 Node.js 运行时版本、SDK调用方式、单次请求/响应大小及超时限制。区分普通云函数与云托管，不自行切换到其他计费产品。
3. 确认服务端 Node SDK 是否可以用环境内身份或服务端 CloudBase API Key 访问 PostgreSQL 的 `rdb()`/RPC；凭证只配置在云函数环境，绝不复制到对话。
4. 确认控制台执行 SQL、表/RLS/GRANT配置及 RPC 的能力；匿名/普通平台用户与服务端角色分别是什么，不把文档数据库 collection 事务用于 PG。
5. 确认 PG 云存储能否提供限定单一随机对象路径的临时上传权限、对象信息校验、短期读取和删除；记录签名有效期和存储权限模型。
6. 只授权指定 `yiqizu-api` 函数的访客调用是否可行，不开全环境函数或数据库匿名读写。

## 之后的隔离探针范围

只有收到经过检查的探针源码及 SQL 包后，再按其版本部署；本说明本身不要求即兴编写后端。所有操作使用已有免费资源。遇到需购买、升级、开启自动续费或公开数据库/存储读写的步骤立即停止并报告。

- 探针函数用独立名称，部署前查重；不覆盖已有函数或网站根目录。前端探针放 `/cn-preview/`。
- 数据表使用 `cn_probe_` 前缀，仅写明确标记的虚构测试值，不上传身份证、真实联系方式或旧站资料。
- 证明匿名 SDK 能调用允许的函数；函数可用服务端身份执行参数化查询和单事务 RPC；两次并发操作只能获得一个最后名额。
- 证明普通平台用户不能直接读取账号、会话、联系方式或执行服务端敏感 RPC。
- 上传一张无个人信息的测试图片，核对限定路径、类型、大小、临时读取及删除；不把永久公共桶当作签名访问验证。
- 记录函数调用/存储操作前后的资源点差值、请求 ID 和脱敏错误；不输出会话令牌、API Key、密码或签名 URL。
- 仅在探针明确清理名单内删除虚构记录/文件；不删除平台系统表或已有测试页，不自行清空环境。

## 1. 目标与成功条件

成功条件分开记录：代码验证通过、CloudBase 实际部署成功、用户大陆网络/微信实测成功，以及用户愿意使用。任一项不能代替另一项。默认域名的小范围试用不等于允许公开投放。

## 3. 技术方案比较与选择

| 方案 | 影响 | 结论 |
| --- | --- | --- |
| React 静态 H5 + CloudBase SDK 云函数 + PostgreSQL | 保留界面和纯业务规则，重写运行时、数据库与文件访问；可以避开默认网站域名的接口响应限制 | 本轮选择 |
| 完整移植现有 Vinext/Worker 后端 | 同时适配服务端渲染、D1 SQL、R2、Cookie 和平台身份，迁移面过大 | 首轮不采用 |
| 香港代理或微信小程序 | 前者仍依赖境外后端，后者需要另一套界面及发布流程 | 不改变已选方向 |

前端新入口拟放在 `yiqizu-cn/`，不修改 `tongzhu-web` 的 Sites 发布配置。使用 React + Vite 生成静态文件，查询参数继续表示列表、详情、我的和运营页，避免静态托管刷新深链接 404。UI 和常量从 v31 按需复制并注明来源；不引入隐藏功能的大型应用入口。

后端一个独立 Node.js 云函数 `yiqizu-api`，仅暴露允许的业务操作。数据库通过官方 Node SDK `rdb()` 或同一 PostgREST 协议调用；跨表原子操作封装为 PostgreSQL 数据库函数，由服务端调用。实际 SDK 版本、执行角色、函数入口及权限先通过能力验证再锁定。

浏览器只持有环境 ID 和允许公开的客户端配置；服务端 API Key、数据库管理凭证不进入前端、源码或聊天。当前工作区没有腾讯云授权；本地负责生成源码、SQL 和部署包，由 WorkBuddy 使用用户自己的已登录环境部署。

## 4. 功能边界

### 保留

- 访客浏览真实帖子、详情，按城市/片区、价格、类型、原始户型和设施筛选，分页 24 条。
- 两类发布：有房招室友、无房找住处；统一走快速登记表单。有房中的房东/中介只保留来源自述和发布权限确认，不新增企业流程。
- 邮箱及密码注册登录、退出、修改密码；注册说明账号未经过邮箱或身份核验。
- 我的资料：昵称、职业、性别、预算、入住时间、片区、个人介绍、室友期待及联系信息；逐项可保存，发布时自动填充。保留用户手填、清空、草稿和原帖的优先级。
- 发帖后本人修改、撤回、照片保留/替换、乐观并发版本检查；修改不新增发帖次数。
- 起租时间、房源几个月起租/求租预计租多久、性别要求、房屋说明和室友期待，沿用既有字段。求租不重新加入设施和合租要求。
- 联系范围由发布者单独选择：登录用户可看或仅运营可见。公开列表、详情、日志和统计均不返回联系方式。
- 免费每天发 3 帖、查看 5 个不同联系对象；北京时间零点重置，重复查看不重复计数，撤回不返还发布次数。
- 运营登录后查看近半年登记、手动跟进、下架、反馈/举报队列，以及近 7 天渠道访问和登记数据。
- 反馈、隐私说明和使用说明；已有个人信息不等于同意公开联系方式。

### 暂不提供

收藏、站内聊天、会员、收款、推广订单、AI、问答建档、保存搜索、人工认证申请、批量房源管理，以及第二套完整发布表单。国内版不显示不能完成的入口；没有假成功或占位支付。

真实邮件找回不计入首轮交付，不展示可用找回按钮；丢失密码可反馈，但运营不能仅凭自述邮箱重置账号。若实际测试说明找回已是必要条件，单独核定发信能力和费用。

## 5. 账号、调用与权限

保留应用自己的邮箱/密码账号，不导入 CloudBase 平台匿名身份作为真实用户。CloudBase SDK 访客身份只是获准调用 `yiqizu-api` 的传输身份；发帖、修改、联系和运营操作还必须校验应用会话。

密码使用服务端随机盐和 PBKDF2-SHA256，至少达到现有 100,000 次迭代基线；密码 8–128 字符且含字母和数字。会话为 32 字节随机令牌，仅 hash 入库，最长 7 天；退出、修改密码会撤销对应会话/全部会话。初版浏览器会话令牌只放 `sessionStorage` 或运行时内存，不写 URL、日志或持久草稿，因此关掉标签页可能需要重新登录。相较原站 HttpOnly Cookie，这是静态 H5 + SDK 的明确取舍；输出纯文本、禁用外部脚本和设置 CSP 以降低 XSS 风险。

所有受保护操作从有效会话解析操作者；忽略请求中的 ownerId、角色、oai-authenticated-*、管理回执等身份声明。管理员由部署环境中的管理员邮箱名单与服务器数据库映射建立，注册参数不能指定管理员。只授权指定业务函数可被访客调用，不开放整个环境的匿名函数权限。

所有业务表启用 RLS 并撤销访客/普通平台用户的直接读写及敏感 RPC 执行权限，服务端角色仅开放必需操作。云函数不能暴露通用 SQL 执行入口。匿名数据库、存储和 RPC 直调的拒绝结果是验收项。

## 6. 数据模型与原子性

业务表统一带 `cn_` 前缀，避免改动平台系统表及后续其他项目：

| 表 | 用途与关键约束 |
| --- | --- |
| `cn_users` | UUID、归一化邮箱唯一、密码 hash/盐、角色、停用状态、资料 JSONB；所有者私有联系字段不进入公开投影 |
| `cn_sessions` | token hash 唯一、user_id、expires_at，支持撤销 |
| `cn_leads` | 两类帖子、公私字段、所有者、住房 JSONB、跟进状态、创建时间及编辑版本；公开状态和运营跟进状态分开 |
| `cn_uploads` | 上传所有者、对象 ID/路径、类型、大小、临时/绑定/待删除状态、绑定帖子和创建时间 |
| `cn_publish_events` | 用户、北京时间日期、幂等请求 ID 唯一；撤回帖子仍留额度记录 |
| `cn_contact_views` | 用户、北京时间日期、联系对象 hash 联合唯一；不记录明文联系值 |
| `cn_events` | 入口来源、事件 ID 唯一、会话 ID、时间；仅记录允许的事件 |
| `cn_feedback` | 反馈/举报、回复方式、处理状态；仅提交者必要回执及运营可读 |
| `cn_rate_limits` | 服务端时间窗限频；不信任客户端自报 IP |

公开列表只读明确允许字段的投影，不使用 `SELECT *` 直接序列化。联系方式、会话、反馈私密字段不能混在公开资料 JSON 中。

发帖使用数据库函数的单事务完成：校验幂等请求、锁定用户当日额度、校验上传归属及状态、写帖子、绑定图片和写发布事件。失败不扣额度，同一请求重试返回同一帖子。并发发第 3/4 帖只允许最后一个合法名额。

编辑使用版本号 compare-and-swap，图片重绑与更新在同事务中；两个编辑最多一个成功，冲突返回 409。旧版本图片不能被另一帖盗用。联系查看在事务中锁定当前用户额度后去重、计数、登记并返回获授权的联系值。额度及所有时间边界以服务端为准。

## 7. 照片与清理

复用前端压缩：大于 512KiB 时最长边缩到 1600px，最多 2 张并行。沿用最多 12 张和原文件 5MB 上限；实际云函数/SDK请求大小更小时，上传前给出明确限制，不采用 Base64 把整张照片塞进云函数 JSON。

上传流程为：应用登录鉴权 → 服务端创建归属明确的上传记录并签发限定路径的临时上传权限 → 上传照片 → 服务端核验对象大小、类型及文件头 → 标记可绑定 → 发帖事务绑定。只允许 JPEG/PNG/WebP，随机对象路径由服务端生成，不允许客户端指定其他用户路径。不开放整个桶公共写入。

具体签名上传接口需在现有 PG 环境验证；若当前免费服务无法提供受限的安全上传路径，停止照片模块部署并报告，不以开放公共读写绕过。服务端上传仅可作为经请求大小验证后的限量替代，不另开付费 COS 桶。

图片通过权限判断后签发短期下载 URL，目标 5 分钟以内，实际期限受平台能力验证约束；不长期保存签名 URL。撤回立即停止新链接签发，但已签发链接可能在有效期内仍能访问，不能承诺即刻失效。

半年沿用 v31 北京时间六自然月规则，月份不足取月末。超过半年在公开查询和运营查询均排除；运营默认 200 条并提供分页，避免被截断的信息无法跟进。成功登记后台任务或运营访问分批清理过期帖子及关联对象；不新增付费定时任务。孤立上传超过 24 小时可清理；访问统计和联系查看记录保留 30 天。额度事件按最小必要期清理，但当前日额度不可误删。

数据库与对象存储不宣称跨系统事务：先隐藏内容并写入待删除对象清单，再逐个删除存储对象，成功后删元数据；失败保留清单下次重试。不删除仍被其他有效内容或资料头像引用的文件。

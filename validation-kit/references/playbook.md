# 可重复的产品验证流程

这套方法复用的是实验设计、发布验收、触达动作和证据记录。产品、城市、渠道和成功门槛需要重新选择。首轮通常7天，复杂或低频需求可以更长；门槛是实验假设，不是行业平均值。

## 1. 把假设缩成一句话

“当【某类人】遇到【近期具体场景】，会用【核心动作】取得【结果】，并愿意做【更强行动】。”

- 双边匹配：找住处/室友 → 提交具体需求 → 双方沟通 → 约看房。
- 单人工具：有待处理材料的人 → 上传一份真实材料 → 得到可用结果 → 再处理第二份/主动分享。
- B2B：有当前业务任务的负责人 → 提供实际样本 → 完成试用 → 约实施讨论/小额付费；不要强套50名消费者的门槛。
- 内容产品：目标读者 → 看完一期 → 主动订阅/转发/付费；曝光和点赞只能算弱信号。

只保留一个核心动作。图片、复杂建档、完整资料、原生App等不属于验证动作时后置。人工撮合可以验证需求，但要分别记录人工投入和用户自行使用情况。

## 2. 发布分四道门

1. **软件就绪**：核心流程、错误提示、重试与重复提交、必要隐私隔离都可用。测试不污染真实指标。
2. **普通用户能进**：用匿名访问验证，不能仅在开发者登录态下打开；运营权限另行保护。
3. **目标地区手机能用**：至少5名目标地区用户，包含安卓/iPhone、移动网络/Wi-Fi、微信内/系统浏览器；不用特殊网络。记录打开耗时、能否提交、失败位置与截图。无法实测就标“待验证”。
4. **真实供给可交付**：双边产品先有少量经同意的真实供需；工具能完成一项真实任务。没有供给时不能用演示数据冒充。

大陆手机打不开时先定位具体环节：站点权限、域名拦截、外部登录、静态资源或服务延迟。按实测结果选择已有表单、H5或新托管方案，不自动购买域名/服务器，不用虚构主体办理备案。没有账号或主体资料时，先完成材料和代码，明确待用户完成的部分。

## 3. 固定获客动作，渠道可换

每个产品只选1—3个能触达目标人群的渠道。渠道的选择依据是“近期有这个问题的人在哪里”，不是固定推荐小红书或微信群。

每个渠道重复同一组动作：

1. 先确认管理员/场地方允许，记录许可与入口。
2. 使用一条含具体场景、收益、时间成本和入口的文案。
3. 回复咨询时先问“何时需要、目前怎么解决、最困难的一步”。符合目标的人才进入有效分母。
4. 分配独立来源链接；固定记录送达/实际看过/开始/完成/有效联系/强行动。
5. 经对方同意，在24—48小时内回访一次，问发生了什么，不问“你觉得这个想法好不好”。未回复不无限追问。
6. 保留拒绝原因：暂时没需求、入口打不开、填写费事、不信任、没合适供给、价值不够。每轮只优先改一个问题。

群管理员拒绝、平台限制外链或渠道没有目标用户时，换经过允许的渠道；不规避平台规则、群发骚扰或伪装普通用户。账号私信、发群、购买流量均需当前用户的明确授权；生成文案不是已经发布。

## 4. 记录真实信号

- 访问会话 ≠ 去重人数 ≠ 合格目标用户。
- 提交 ≠ 有效需求；有效需求要核实具体场景、时间和联系方式。
- 联系点击 ≠ 双方沟通；双方沟通 ≠ 约定下一步。
- 双边产品用配对编号记录两个人，避免将两条登记误算为两对。
- 同事帮忙、测试、演示、补贴完成、运营代办分别标记，不能作为自然需求。
- 记录现金与人力成本；访谈补贴不按注册或好评发放。

结果字段没有证据时留空，不补0。没有足够目标流量时不能判“没人需要”；流量足够却没人提交，先查表达和阻力；有人提交但无法匹配，先查供给；有人认真使用却不继续，查结果质量或付费价值。

## 5. 复盘与复制

第一轮结束输出：最强证据、主要流失点、真实成本、需要改变的一个变量、继续/调整/暂缓的理由。下一轮复制配置与记录格式，保留上一轮结果作为对照；不把阈值、城市或获客渠道变成固定教条。

另一产品启动时，只替换配置并重做四道发布验收。已有触达权限、公开权限、服务账号、真实用户资料不自动跨产品复用。
